# Architecture

## System boundary

Morning Call is a browser client backed by a small Node.js server. The server serves static assets and brokers the initial WebRTC SDP exchange with the OpenAI Realtime API. The permanent API key never enters the browser.

```text
Browser UI ── SDP offer ──▶ Local broker ──▶ Realtime API
     │                           │
     ├── camera preview          └── API key boundary
     ├── localStorage
     └── WebRTC audio/data ◀──────── Realtime session
```

## Client responsibilities

- Acquire camera and microphone streams.
- Render the call interface.
- Establish the WebRTC peer connection.
- Process Realtime data-channel events.
- Execute the `record_weight` tool locally.
- Store and render recent weight observations.
- Recover to manual entry when voice is unavailable.

The client deliberately does not upload camera video to the application server or OpenAI.

## Server responsibilities

- Serve files from `src/client`.
- Report configuration status through `/api/health`.
- Validate SDP input size and shape.
- Attach server-owned Realtime session configuration.
- Forward the offer to `/v1/realtime/calls`.
- Return the SDP answer without exposing the API key.

The Realtime call flow follows the official OpenAI API's server-brokered WebRTC pattern.

## Data flow

### Starting a call

1. The user taps **CALL**.
2. The browser requests camera and microphone access.
3. The client creates a WebRTC offer and an `oai-events` data channel.
4. The local broker forwards the SDP and trusted session configuration.
5. The client applies the returned SDP answer.
6. On `session.created`, the client asks the assistant to begin.

### Recording weight

1. The assistant hears the user's answer.
2. The model emits `record_weight` with a numeric pounds value.
3. The client validates and stores the observation locally.
4. The client returns a function result through the data channel.
5. The assistant acknowledges the saved value.

## Trust boundaries

- **Deterministic data boundary:** Client code validates weight before persistence.
- **Secret boundary:** Only the server reads `OPENAI_API_KEY`.
- **Media boundary:** Camera video remains attached only to the local preview.
- **Future Observer boundary:** Visual measurements will be generated by local computer vision, never invented by the language model.

## Extension points

- `src/client/weight.js` can move from localStorage to an encrypted local database.
- `src/server/realtime.mjs` can use short-lived client secrets or a sideband controller.
- Camera frames can feed an on-device Observer without changing the Realtime interface.
- Structured Observer summaries can be introduced as additional assistant tools.
